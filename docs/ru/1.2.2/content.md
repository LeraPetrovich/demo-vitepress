## Тестовые сценарии {#test-cases}
Тестовые сценарии в ATR описываются в виде кода Javascript с использованием фреймворка Cypress и библиотеки [Chai](https://github.com/chaijs/chai).

Каждый сценарий должен быть заключен в конструкцию `describe(...)`. 
Сценарий может содержать несколько тестов. Каждый новый тест описывается в своем блоке `it(...)`.

**Шаблон пустого сценария с одним тестом**

```js
describe('Название сценария', () => {
    // Хук
    before(() => {
        // Команды
        // ...
    });

    it('Название теста', () => {
        // Команды
        // ...
    });
});
```

Сценарии могут сопровождаться блоками `before`, `beforeEach`, `after`, `afterEach`, которые срабатывают до либо после тестов. Подробнее в [Хуки](#hooks)

Тест представляет собой набор команд из разных категорий. 
Команды всегда начинаются с `cy.`, и могут вызываться либо через имя (к примеру `cy.get(...)`), либо через аргумент (к примеру `cy.task('log', ...)`)

**Пример сценария с несколькими тестами и хуками**

```js
// Глобальная переменная(ые), доступные для использования из любого участка сценария
var g_ticketSubject = generateUniqueTicketName();

describe('Создание Инцидента с Портала Самообслуживания', () => {
    // Хук, который выполняется единожды при старте сценария
    before(() => {
        // Команда из библиотеки методов SimpleOne для входа в систему под указанной учетной записью
        cy.loginSimpleOne("z_end_user");

        // Команда из категории 'Действия' для навигации по страницам
        cy.visit('/portal');
        
        cy.visit('/portal/record?table_name=itsm_incident&view=Service%20Catalogue');
    });

    // Тест №1
    it('Нельзя создать Инцидент без заполнения Темы на Портале', () => {
        // Две команды в цепочки
        // Первая из категории 'Запросы' для поиска элемента на странице
        // Вторая из категории 'Проверки' для проверки состояния элемента. В нашем случае, проверяем неактивность кнопки Сохранить
        cy.get('[data-test="form_button__save-ui-button"]').should('be.disabled');

        // Команда из категории 'Другие Команды' для записи сообщения в логи
        cy.task('log', `Заполняем поле значением ${g_ticketSubject}`);

        cy.get('[data-test="subject-field-textarea"]').find("textarea").type(g_ticketSubject);

        cy.get('[data-test="form_button__save-ui-button"]').should('be.enabled');

        // Две команды в цепочки, где вторая из категории 'Действия' выполняет нажатие на кнопку Сохранить
        cy.get('[data-test="form_button__save-ui-button"]').click();
    });

    // Тест №2
    it('...', () => {
        ...
    });

    // Тест №N
    it('...', () => {
        ...
    });

    // Хук, который выполняется после каждого теста
    afterEach(() => {
        cy.task('log', 'Завершен тест');
    });
});

// Вспомогательный метод для формирования уникального имени
function generateUniqueTicketName() {
    var uuid = 'xxxx-xxxx-xxx-xxxx'.replace(/[x]/g, (c) => {
        const r = Math.floor(Math.random() * 16);
        return r.toString(16);
    });

    return "Тестовый Инцидент (" + uuid + ")";
}
```
В Тестовом сценарии возможно обратиться к полям самого тестового сценария, используя переменные окружения: 

- `test_case_name` - название сценария;
- `test_case_description` - описание сценария;
- `test_case_folder_name` - название папки в которую добавлен тестовый сценарий;
- `execution_plan_name` - название плана выполнения в котором запускается тестовый сценарий;
- `environment_name` - название окружения;
- `environment_url` - ссылка на окружение;

В JESM ATR поля Тестового сценария хранятся в объекте Cypress.env().  

**Пример сценария получения доступа к полям Тестового сценария**

```js
it('Пример использования переменных окружения в работе с полями Тестового сценария', () => {
    // Получаем значение переменной Тестового сценария 'test_case_name'
    const case_name = Cypress.env('test_case_name'); //название сценария
    
    // Выводим в лог
    cy.task("log", `Название сценария: ${case_name}`);
    // Изменяем значение названия сценария для дальнейшего использования в текущем тестовом сценарии
    Cypress.env('test_case_name', `${case_name}_DONE`);
    });
```

## Команды

JESM ATR поставляется с готовым набором команд и также позволяет создавать [собственные](#custom-commands).

Команды можно классифицировать следующим образом:

- `query (запросы)` - команды, считывающие состояние вашего приложения
- `assertion (проверки)` - команда, проверяющая заданное состояние
- `action (действия)` - взаимодействуйте с вашим приложением так, как это делал бы пользователь
- `other (другие)` -  любая другая команда, полезная для написания тестов
- `library (библиотека)` -  команда, адаптированная под выполнение определенного действия в целевой системе

Команды могут быть объединены в цепочки, при этом каждая команда передает "объект" следующей команде, пока цепочка не закончится или не возникнет ошибка.

Подробнее о том, как команды объединяются в цепочку, читайте по ссылке
[Введение в цепочки команд](https://docs.cypress.io/app/core-concepts/introduction-to-cypress#Chains-of-Commands).


### Запросы

Запросы - это команды для чтения состояния вашего приложения.
Они возвращают объект для дальнейших действий или проверок и при необходимости повторяют попытку, чтобы убедиться, что полученный DOM-элемент или другие данные всегда актуальны.

| Команды                                        | Применение                                                                                                      |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `.as()`                     | Присвоить алиас для последующего использования. Ссылаться на алиас позже в запросе  `cy.get()` или команде `cy.wait()`. |
| `.children()`         | Получить дочерние элементы каждого элемента в наборе DOM-элементов.                                             |
| `.closest()`           | Получить первый родительский элемент, который соответствует селектору.                                                   |
| `.contains()`         | Выберите элемент DOM по текстовому содержимому.                                                                      |
| `.document()`         | Получить объект window.document активной страницы.                                                              |
| `.eq()`                     | Выберите элемент DOM по индексу из коллекции.                                                           |
| `.filter()`             | Отфильтровать элементы по селектору.                                                                           |
| `.first()`               | Выбрать первый элемент в коллекции.                                                                     |
| `.get()`                   | Найти элементы DOM по селектору или получить ранее созданный алиас с помощью команды  `.as()`.               |
| `.hash()`                 | Получить хеш URL активной страницы.                                                                       |
| `.its()`                   | Получить значение свойства у ранее переданного объекта.                                                  |
| `.last()`                 | Выбрать последний элемент в коллекции.                                                                      |
| `.location()`         | Получить объект window.location активной страницы.                                                       |
| `.not()`                   | Отфильтровать выбранные элементы по селектору.                                                                  |
| `.parentsUntil()` | Получить все родительские элементы вплоть до указанного селектора.                                                                  |
| `.prev()`                 | Получить предыдущий родственный элемент.                                                                          |
| `.prevAll()`           | Получить все предыдущие родственные элементы.elements.                                                                         |
| `.prevUntil()`       | Получить все последующие предыдущие родственные элементы до указанного селектора.                                     |
| `.shadow()`             | Перейти в теневой DOM элемента.                                                                |
| `.siblings()`         | Получить все родственные элементы.                                                                                  |
| `.title()`               | Получить свойство document.title активной страницы.                                                      |
| `.url()`                   | Получить URL активной страницы.                                                                            |
| `.window()`             | Получить объект window активной страницы.                                                                |

### Проверки

Проверки — это команды, которые проверяют состояние вашего приложения. Они приостанавливают выполнение теста до тех пор, пока указанное условие не будет выполнено или не истечет время ожидания. 


| Команда                             | Использование                                                                                                      |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `.and()`       | Алиас для .should(). Выполняет проверку состояния вашего приложения.                                            |
| `.should()` | Выполняет проверку состояния вашего приложения. Проверки автоматически повторяются до тех пор, пока они не пройдут или не истечет время ожидания. |

### Действия

Действия — это команды, которые взаимодействуют с вашим приложением так, как это делал бы пользователь. Они ждут, пока элементы станут активными, прежде чем взаимодействовать со страницей.


| Команда                                             | Использование                                                                                    |
| --------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `.check()`                   | Проверить элементы checkbox или radio.                                                        |
| `.clear()`                   | Очищает значение поля input или textarea.                                                 |
| `.click()`                   | Кликает по элементу DOM.                                                                     |
| `.dblclick()`             | Двойной щелчок по элементу DOM.                                                              |
| `.rightclick()`         | Кликает правой кнопкой мыши по элементу DOM.                                                               |
| `.scrollIntoView()` | Прокрутите элемент в область просмотра.                                                             |
| `.scrollTo()`             | Прокрутите до определенной позиции.                                                           |
| `.select()`                 | Выбирает  `<option>` внутри элемента `<select>`.                                                |
| `.selectFile()`         | Выбирает файл в HTML5-элементе ввода или имитирует перетаскивание файла в браузер. |
| `.type()`                     | Вводит текст в элемент DOM.                                                                 |
| `.uncheck()`               | Снятие флажка с чекбокса(ов).                                                                    |

### Библиотеки методов

JESM ATR предоставляет библиотеку готовых команд, адаптированных к целевой системе.
Всю библиотеку смотри в соответствующем разделе.

## Утилиты

Допускается использование в тестах библиотек доступных напрямую через глобальный объект JESM.

| Утилита                                         | Использование                                                                                                                                    |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `Cypress.$`                 | JESM автоматически включает [jQuery](http://jquery.com/) и предоставляет его как `Cypress.$`.                                               |
| `Cypress._`                 | JESM автоматически включает [lodash](https://lodash.com/) и предоставляет его как `Cypress._`.                                              |

## Хуки {#hooks}

Хуки позволяют выполнять команду(ы) в заданный момент (перед всеми тестами, перед каждым тестом и т.д) жизненного цикла тестового сценария.
К примеру, в хуке `before` можно вызвать команду входа в систему, чтобы не вызывать ее в каждом отдельном тесте.

## Учетные записи {#credentials}

JESM ATR позволяет проводить тестирование под разными пользователями. Это достигается благодаря указанию учётной записи в командах входа ([`.loginSimpleOne()`](/ru/1.2.2/simpleone/login)) в систему. 

Учетные записи предварительно должны быть добавлены в соответствующий раздел меню.

## Асинхронные команды {#async-commands}

Часть команд должна вызываться с использованием ключевого слова `await`, которое позволяет дождаться результата выполнения.

В описании таких команд явно указана необходимость использования `await`. Смотри пример `cy.getUserID()` 

::: warning
Важно, что такие команды необходимо вызывать только внутри функции async, которую можно объявить в одной из следующих форм

```js
_asyncRun();

async function _asyncRun() {
    // код
}

/* ЛИБО */

(async () {
    // код
})();
```
:::


**Пример правильного использования в тесте команд с ключевым словом await**

```js
describe('Сценарий 1', () => {
    before(() => {
        // ... войти в систему ...
    });

    it('Тест 1.1', () => {
        cy.openRecord('sys_email_account', '157425284611357796'); // Команда 1 без await
        cy.waitFormLoaded(); // Команда 2 без await

        _asyncRun();

        // Объявление функции типа async, внутри которой можно вызывать команды c обязательным ключевым словом await
        async function _asyncRun() {
            var form = await cy.getForm();  // Команда 3 с await. Ждем ее завершение и получаем результат в переменную          
            expect(form).to.not.be.empty;

            cy.openRecord('itsm_incident', '157425284611357782'); // Команда 4 без await
            cy.waitFormLoaded(); // Команда 5 без await
        }
    });
});
```

**Пример неправильного использования команды с ключевым словом await**

```js
describe('Сценарий 2', () => {
    before(() => {
        // ... войти в систему ...
    });

    it('Тест 2.1', () => {
        cy.openRecord('sys_email_account', '157425284611357796'); // Команда 1 без await
        cy.waitFormLoaded(); // Команда 2 без await

        // Неверный вызов
        // Произойдет ошибка Unexpected reserved word 'await' и тест не запустится
        var form = await cy.getForm();  // Команда 3 с await         
        expect(form).to.not.be.empty;
    });
});
```

**Пример неправильного использования команды с ключевым словом await**

```js
describe('Сценарий 3', () => {
    before(() => {
        // ... войти в систему ...
    });

    it('Тест 3.1', () => {
        cy.openRecord('sys_email_account', '157425284611357796'); // Команда 1 без await
        cy.waitFormLoaded(); // Команда 2 без await

        // Пропущено ключевое слово await
        var form = cy.getForm();  // Команда 3 с await
        // Произойдет ошибка в тесте т.к form будет undefined. Система не будет дожидаться окончания выполнения команды cy.getForm выше     
        expect(form).to.not.be.empty;
    });
});
```

## Cобственные команды {#custom-commands}

В некоторых случаях (к примеру необходимость нестандартного входа в систему и т.д) при отсутствии готовых команд пользователь JESM ATR модуля может создавать собственные команды для переиспользования в сценариях.
Собственные команды создаются в интерфейсе модуля, пункт 'Команды'.

::: info
Рекомендуется использовать в названии таких команд префикса (к примеру u_), чтобы отличать их от других команд.
:::

**Пример собственной команды**

```js
Cypress.Commands.add("u_loginKeycloak", (credentialName, authUrl, redirectURL, btnLoginSelector = '#kc-login') => {
    // Рекомендуется добавлять в собственные команды проверку входных параметров
    if (!credentialName) {
        throw new Error(`Команда u_loginKeycloak: Укажите название учетной записи (пункт 'Настройки->Система->Учетные записи') для входа !`);
    }

    if (!authUrl) {
        throw new Error(`Команда u_loginKeycloak: Укажите путь в параметре authUrl !`);
    }

    if (!redirectURL) {
        throw new Error(`Команда u_loginKeycloak: Укажите путь в параметре redirectURL !`);
    }

    // Параметры учетной записи логин/пароль (Администрирование-Система-Учетные записи) читаются с использованием конструкций ниже
    const username = Cypress.env(credentialName + "_login")
    const password = Cypress.env(credentialName + "_password")

    cy.origin(
        authUrl,
        {
            args: {
                username,
                password,
                btnLoginSelector
            },
        },
        ({ username, password, btnLoginSelector }) => {
            cy.get('#username').type(username)
            cy.get('#password').type(password, { log: false })

            cy.get(btnLoginSelector).click();
            cy.get('#input-error-container-username').should('not.exist');
        }
    )

    cy.url().should('equal', redirectURL)
});
```
